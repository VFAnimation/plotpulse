# PlotPulse

An interactive sales page for a residential colony, with a private dashboard for the builder. By [VF Animation](https://github.com/VFAnimation).

This repo is set up for **Chohak Land** (81 plots, 22 shops). The layout is traced from the AutoCAD plan; names, numbers and documents marked "sample" are placeholders.

**Public page** (`/`, for buyers):
- 3D model of the colony at the top, showing live availability.
- Clickable master plan of every plot and shop: area in gaj and sq ft, dimensions, facing, corner / park-facing.
- Colours: **green** = available, **yellow** = available and in demand (automatic, from how many people view it), **grey** = allotted (set by the builder). E.W.S. plots are hatched and can't be selected.
- "N people viewed this plot" on popular plots.
- "Ask the price on WhatsApp" on every available plot and shop, with the unit number already typed in. No prices on the page.
- 360° tour, Google Maps location, nearby places, RERA number and approval PDFs.

**Builder dashboard** (`/builder/`, password protected):
- Visitors, plot views and WhatsApp enquiries, compared with the previous period.
- Demand map: which plots and shops people open most.
- What buyers want: interest by plot size, facing, and park-facing / corner / shop.
- Units with many views but few enquiries (worth checking the price).
- Which hoarding, brochure or link brings visitors, visitors per day, busiest times.
- Mark plots and shops as allotted or available; the public page follows.
- Settings for the "in demand" rule.

No personal data is collected. Each browser gets a random anonymous tag so one person opening a plot twice counts once. Enquirers' names and numbers reach the builder only on WhatsApp.

## Try it on your computer

```bash
cd plotpulse
python3 -m http.server 8000
```

Open <http://localhost:8000> for the public page and <http://localhost:8000/builder/> for the dashboard (demo password `demo123`, any email). Opening `index.html` by double-clicking won't work, because the browser blocks loading `plots.json` from a file; use the command above or the published link.

### Demo mode and live mode

| | Demo mode | Live mode |
|---|---|---|
| When | `supabase.url` in `colony/config.js` is empty | Supabase URL and key filled in |
| Data | Sample visitor activity made up in the browser, plus your own clicks | Real visitors, shared by everyone |
| Allotting | Saved in your browser only | Saved for everyone |
| Use it for | Showing builders what they get | A real launch |

Demo-mode numbers are invented. Don't put a public page live in demo mode.

## Folder structure

```
index.html              Public page
builder/index.html      Builder dashboard
assets/                 Code and styles (same for every colony)
  store.js              Data layer: demo mode and Supabase mode
  plan.js               Draws the master plan (map, hero model, heat map)
  public.js / .css      Public page
  dashboard.js / .css   Builder dashboard
  vendor/pannellum/     360° viewer (MIT licence)
colony/                 Everything specific to one colony
  config.js             Name, WhatsApp number, map pin, RERA, highlights, tour
  plots.json            Layout and every plot / shop
  panos/                360° images
  docs/                 Approval PDFs
supabase/schema.sql     Database setup for live mode
tools/                  Helper scripts
```

For a new colony only `colony/` changes. Copy the repo, swap the colony files, publish.

## Setting up a colony

1. **Details**: edit `colony/config.js`: colony and builder name, WhatsApp number (country code, no `+`), map pin and address, nearby places, RERA number, documents, highlights, tour scenes. Set `heroImage` to an aerial render if you have one; otherwise the 3D plan model is shown.
2. **Layout**: `colony/plots.json` holds the roads, park, amenities and each unit's rectangle. For Chohak Land it's generated by `tools/build_chohak_plan.py` from measurements off the CAD PDF (`python3 tools/build_chohak_plan.py`). For another colony, copy that script and change the measurements.
3. **Plot details**: put the builder's sheet in the format of `tools/plot_sheet_template.csv` (unit number, type, width, depth, facing, corner, park-facing, status), save as CSV and run
   `python3 tools/update_plots_from_csv.py builder_sheet.csv`
   Shops are numbered `S1`, `S2`…; E.W.S. rows use type `ews`.
4. **360° tour**: export 2:1 equirectangular JPGs from your 3D scene (6144×3072 loads well on phones) into `colony/panos/` and list them in `config.js` → `tour.scenes`. Hotspot `yaw` is left/right in degrees (0 = centre of the image), `pitch` is up/down. The three images there now are placeholders.
5. **Documents**: PDFs in `colony/docs/`, listed in `config.js` → `trust.documents`. The ones there now are placeholders.

### QR codes for hoardings and brochures

Point each QR code at the public link with its own `src` tag, for example:

```
https://<your-link>/?src=hoarding-highway
https://<your-link>/?src=brochure-expo
```

The dashboard's Marketing section shows visitors and enquiries per tag. Use short names, lowercase, no spaces. `tools/make_qr.py` can make them in bulk if you want (`pip install "qrcode[pil]"`, list them in `tools/qr_sources.csv`, run `python3 tools/make_qr.py https://<your-link>/`).

## Publishing (free)

**GitHub Pages**: upload the files to the repo, then Settings → Pages → Source: *Deploy from a branch* → Branch `main`, folder `/ (root)` → Save. The site appears at `https://<username>.github.io/<repo>/` within a couple of minutes, and the dashboard at `…/builder/`. On a free GitHub account the repo must be public for Pages.

To keep the code private, use **Cloudflare Pages** (free, allows commercial use): connect the repo, no build command, output folder `/`.

## Going live with Supabase (free tier)

1. Create a project at [supabase.com](https://supabase.com), one per colony.
2. SQL Editor → New query → paste `supabase/schema.sql` → Run.
3. Authentication → Sign In / Providers → turn **off** "Allow new users to sign up".
4. Authentication → Users → Add user: the builder's email and a password. That's the dashboard login.
5. Project Settings → API → copy the **Project URL** and the **anon public** key into `colony/config.js` → `supabase`. The anon key is meant to be public; the rules in `schema.sql` decide what it can do.

Anyone can add an anonymous event and read plot status, settings and per-plot view counts. Only the signed-in builder can read raw activity, allot plots and change settings.

A free Supabase project may pause after a long stretch with no visitors. Restore it from the Supabase dashboard if that happens.

## How the numbers work

- **Viewers of a plot** = different browsers that opened it in the chosen window (default 7 days). The same browser opening it again the same day isn't counted again.
- **In demand (yellow)** = the top 20% most-viewed *available* plots and shops, once they pass the minimum viewer count. Both are adjustable in the dashboard.
- **"N people viewed"** shows only from the minimum count (default 10), so quiet plots don't look unwanted.
- **Enquiries** = taps on the WhatsApp button. Whether the message was actually sent is only visible on the builder's WhatsApp.
- Counts are approximate: one person on two devices counts twice, and clearing browser data resets their tag.
